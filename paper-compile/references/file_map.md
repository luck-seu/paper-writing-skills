# Template: file_map.md (machine view)

The file map: the paper as an assembly of files, in reading order —
every `.tex` file with its **role** (macro source vs prose,
classified by content, never by name), whether paper.tex actually
`\input`s it, what is inside (headings for prose, a definition
count for macro sources), and which files exist on disk but are not
yet included — the in-progress writing state. This is the artifact
other skills reference: paper-scaffold's section-file lookup starts
here, and the notation view takes its macro sources from the same
classification.

**Verdict: script-perfect.** `\input` matching, role
classification, heading/label extraction, and the
included/not-included split are mechanical.

**No hardcoded file names** (author ruling, 2026-11-02): discovery
finds every `.tex` (root-level plus a `sections/` tree) except
`paper.tex` — the one documented anchor of the paper root. A file
is a **macro source** iff it holds at least one macro definition
and every non-comment line outside definition bodies is itself
LaTeX markup (starts with `\`, `{`, or `}`) — a file carrying
prose sentences is prose. `commands.tex` / `macros.tex` /
`keywords.tex` style names are found by this rule, never assumed.

drafted section that is not yet wired into the paper.

## Source & regeneration

paper.tex `\input`/`\include` markers, matched by name against the
discovered `.tex` inventory, plus a heading scan (`\section`,
`\subsection`, `\subsubsection`, `*` variants; titles raw — macros
unexpanded) over each prose file's content text
(`macromap.read_content`: comment-stripped, `\eat`-style swallow
calls blanked — an eaten heading is not listed) and the definition
walk of `core/macromap.py` (`scan_file`) over each macro source.
`python3 scripts/compile.py file_map`.
